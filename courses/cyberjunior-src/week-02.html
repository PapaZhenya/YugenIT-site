Конспект

Почти каждая атака проходит через сеть, поэтому понимание сетевого стека — обязательная база. Данные передаются по уровням; каждый добавляет свой заголовок.

Стек TCP/IP (упрощённо)

  • Канальный — передача внутри локального сегмента (MAC-адреса).
  • Сетевой (IP) — маршрутизация между сетями по IP-адресам.
  • Транспортный (TCP/UDP) — доставка до службы. TCP надёжен и с установкой соединения, UDP быстр и без гарантий.
  • Прикладной — HTTP, DNS, SMTP.

Порты и рукопожатие TCP. IP указывает на хост, порт — на службу. TCP открывается через three-way handshake: SYN → SYN-ACK → ACK.

DNS и HTTP против HTTPS. DNS превращает имя в IP; вокруг него строятся фишинг и отравление кэша. HTTP передаёт данные открытым текстом (включая логины), HTTPS добавляет TLS-шифрование.

Порты наизусть: HTTP 80, HTTPS 443, SSH 22, FTP 21, SMTP 25, DNS 53, RDP 3389.

Глубже в тему

Перехват трафика и почему HTTPS важен для ИБ

В общей сети (открытый Wi-Fi) злоумышленник может «слушать» чужой трафик. Если сайт на HTTP, логины и данные видны открытым текстом. HTTPS шифрует их, и перехваченное становится бесполезным. Для безопасника это база: незашифрованные протоколы — приоритетная цель и для атаки, и для защиты.

TCP-флаги и что такое «сканирование портов»

TCP-соединение открывается рукопожатием (SYN → SYN-ACK → ACK). Инструменты сканирования (Nmap) играют с этими шагами, чтобы узнать, какие порты открыты, не завершая полное соединение. Понимание рукопожатия помогает читать логи и распознавать сканирование — типичный первый признак подготовки атаки.

Модель OSI глазами защитника

Каждый уровень — свой класс угроз: на канальном — подмена MAC/ARP, на сетевом — подмена IP, на транспортном — сканирование, на прикладном — атаки на веб. Зная уровень, ты понимаешь и вектор атаки, и где ставить защиту. Модель OSI — не только теория, но и карта угроз.

Ещё один пример: опасность открытого Wi-Fi

Ты в кафе, заходишь на сайт по HTTP и вводишь пароль. Любой в той же сети с простым снифером видит его открытым текстом. Если бы сайт был на HTTPS, перехватчик увидел бы только шифрованный мусор. Вывод для защиты: используй HTTPS и VPN в публичных сетях; для атаки этот сценарий показывает, почему открытые протоколы — лёгкая добыча.

Пошаговый разбор: что видно при входе на сайт

  1. Устройство узнаёт IP сайта через DNS.
  2. Открывает TCP-соединение (рукопожатие) на порт 443.
  3. Согласуется TLS-шифрование (для HTTPS).
  4. Идёт зашифрованный обмен данными.
  5. В открытом Wi-Fi посторонний видит: к какому IP ты подключился, но не содержимое (для HTTPS).

Мини-проект: карта портов и рисков

Для учебной машины (или своего ПК) составь таблицу:

  • какие порты открыты (узнаешь в модуле 4 через Nmap, пока — известные);
  • какая служба за каждым;
  • чем опасен открытый порт;
  • нужен ли он вообще (лишнее — закрыть).

Это первый шаг к сокращению поверхности атаки.

Ключевые термины

  • TCP/UDP — надёжный / быстрый транспорт.
  • Порт — «дверь» к службе (22 SSH, 80 HTTP, 443 HTTPS, 53 DNS).
  • DNS — имя → IP.
  • HTTP vs HTTPS — открыто / зашифровано.
  • Рукопожатие TCP — SYN → SYN-ACK → ACK.
  • Снифер — инструмент перехвата трафика (напр. Wireshark).

Частые ошибки и мифы

  • Миф: в частной сети можно не шифровать. Внутренний злоумышленник тоже угроза.
  • Ошибка: игнорировать открытые порты. Каждый лишний порт — потенциальный вход.
  • Миф: HTTPS = сайт безопасен полностью. HTTPS защищает канал, но не сам сайт от уязвимостей.
  • Ошибка: путать IP и порт. IP — устройство, порт — служба.

Частые вопросы (FAQ)

  • Wireshark — это «хакерский» инструмент? Нет, это стандартный анализатор для диагностики и защиты.
  • Почему HTTPS так важен? Он шифрует данные, обесценивая перехват.
  • Что такое сканирование портов? Проверка, какие службы доступны на устройстве.
  • VPN защищает в открытом Wi-Fi? Да, он шифрует твой трафик поверх сети.

Шпаргалка модуля

  • Рукопожатие: SYN → SYN-ACK → ACK.
  • Каждый уровень OSI = свой класс угроз.
  • Открытый порт = потенциальная точка входа.

Лабораторная работа

Часть A. Развёртывание лаборатории

  1. Установите VirtualBox и создайте ВМ Kali Linux.
  2. Настройте два адаптера: NAT (интернет) и Host-Only/Internal (изолированная сеть).
  3. Проверьте связность ping внутри лаб-сети.

Часть B. Захват трафика HTTP

  1. Запустите Wireshark на интерфейсе лаб-сети.
  2. Откройте HTTP-ресурс с формой ввода.
  3. Найдите three-way handshake (SYN, SYN-ACK, ACK).
  4. Отфильтруйте HTTP и найдите данные формы в открытом виде.

Часть C. Сравнение с HTTPS

  1. Повторите захват при открытии HTTPS-ресурса.
  2. Убедитесь, что содержимое зашифровано.
  3. Зафиксируйте вывод: что видно в HTTP и скрыто в HTTPS.

Дополнительные лабораторные

Часть D. Сравни HTTP и HTTPS в Wireshark

  1. Захвати трафик при входе на HTTP-страницу с формой — найди данные открытым текстом.
  2. Повтори с HTTPS — убедись, что содержимое зашифровано.
  3. Сделай вывод, почему это критично для безопасности.

Часть E. Инвентаризация портов

  1. Составь список стандартных портов и служб.
  2. Для трёх из них опиши, чем опасна их доступность из интернета.
