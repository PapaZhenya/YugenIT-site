Третья неделя блока «Фундамент» учит уверенно работать в командной строке Linux, разбираться в модели прав доступа и находить следы событий в системных логах Linux и Windows.

Цели модуля

  • Уверенно навигировать в Linux из командной строки
  • Понимать модель прав и принцип наименьших привилегий
  • Находить и читать системные логи Linux и Windows

Как это выглядит (схема)

Права доступа в Linux (rwx):

-rwxr-x---   владелец: rwx   группа: r-x   остальные: ---
 ^ файл       (чтение/запись/выполнение)
777 = rwx для ВСЕХ = опасно

Где искать следы (логи):

Linux:   /var/log/auth.log  (входы, sudo)
         /var/log/syslog    (система)
Windows: Event Viewer -> Security (4624 вход, 4625 отказ)

Конспект

Инструменты ИБ живут в командной строке, а расследование начинается с логов.

Файловая система и права Linux. Дерево от корня /, всё есть файл. Права — три набора (владелец/группа/остальные) в виде rwx. chmod меняет права, chown — владельца, sudo даёт временные привилегии root. Избыточные права (777) — частая причина компрометации.

Логи как источник истины. В Linux — /var/log (auth.log — входы, syslog — система). В Windows — Event Viewer: Security (входы 4624 успешный, 4625 неудачный), System, Application.

Active Directory на пальцах. В корпоративной среде Windows-машины в домене под управлением Active Directory — каталога пользователей, групп и политик. Понимание AD критично для Blue Team, потому что именно его атакуют для захвата всей сети.

Глубже в тему

Пользователи, группы и root

В Linux у каждого процесса есть владелец. root — суперпользователь, может всё. Обычные пользователи ограничены; sudo даёт временное повышение до root. Атакующие стремятся именно к root («повышение привилегий»), а защита — держать пользователей на минимуме прав. Понимание этой модели — основа и атаки, и защиты.

Повышение привилегий (в двух словах)

Часто атакующий сначала получает доступ обычного пользователя, а затем ищет способ стать root: неверные права на файлы, уязвимые программы с флагом повышения, слабые настройки sudo. Задача защитника — не оставлять таких лазеек. На этом курсе мы смотрим на это концептуально и только в лаборатории.

Процессы, службы и автозагрузка

Система — это множество работающих процессов и служб. Вредонос часто маскируется под системный процесс и прописывается в автозагрузку, чтобы пережить перезагрузку. Поэтому умение смотреть список процессов и автозапуск — базовый навык расследования (пригодится в неделях 9–10).

Ещё один пример: опасность прав 777

Разработчик поставил конфигурационному файлу права 777 «чтобы работало». Теперь любой пользователь системы может его прочитать и изменить — включая секреты в нём. Атакующий, получивший даже низкие права, подменяет файл и повышает привилегии. Вывод: права — не формальность, а поверхность атаки. Правильно — минимально необходимые права.

Пошаговый разбор: находим неудачные входы в логе

  1. Открой /var/log/auth.log.
  2. Отфильтруй строки со словами Failed password: grep "Failed password" auth.log.
  3. Посчитай их: добавь | wc -l.
  4. Найди, с каких IP шли попытки: grep "Failed password" auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn.
  5. Много попыток с одного IP → вероятный перебор паролей.

Мини-проект: шпаргалка команд + аудит прав

Собери свой рабочий инструмент:

  • шпаргалка из 20 команд Linux с описанием;
  • на учебной ВМ найди файлы с избыточными правами (например, доступные на запись всем);
  • предложи, как их исправить;
  • оформи короткий отчёт «аудит прав».

Ключевые термины

  • root — суперпользователь Linux.
  • sudo — временное повышение прав.
  • rwx / chmod — права доступа и их изменение.
  • auth.log / syslog — журналы Linux.
  • Event ID 4624/4625 — вход/отказ в Windows.
  • Повышение привилегий — получение более высоких прав.
  • Автозагрузка — механизм запуска при старте (частое место персистенции).

Частые ошибки и мифы

  • Миф: логи никто не читает, значит, они не нужны. Логи — главный источник истины при расследовании.
  • Ошибка: ставить 777 «чтобы работало». Это открытая дверь.
  • Миф: root нужен для всего. Наоборот — работай с минимумом прав.
  • Ошибка: доверять history -c. Следы часто остаются в других логах.

Частые вопросы (FAQ)

  • Обязательно ли знать Linux? Да, это основной инструмент безопасника.
  • Зачем читать логи вручную, если есть SIEM? Понимание логов — база; SIEM лишь автоматизирует.
  • Что важнее — Linux или Windows? Оба: серверы часто Linux, корпоративная среда — Windows/AD.
  • Что такое повышение привилегий? Получение более высоких прав, чем выданы изначально.

Шпаргалка модуля

  • Навигация: pwd ls -la cd cat less grep head tail.
  • Права: chmod, модель rwx (владелец/группа/остальные), 777 — опасно.
  • Повышение: sudo; цель атакующего — root.
  • Логи: /var/log/auth.log, syslog; Windows — Event Viewer (4624/4625).
  • Считать неудачные входы: grep "Failed password" auth.log | wc -l.

Лабораторная работа

Часть A. Навигация и файлы

  1. Освойте: pwd, ls -la, cd, cat, less, head, tail, grep.
  2. Создайте каталог и файлы, потренируйтесь перемещаться и просматривать.

Часть B. Права доступа

  1. Создайте пользователя и файл; меняйте права через chmod.
  2. Проверьте, что может и не может другой пользователь.
  3. Покажите, почему права 777 на файл с секретом опасны.

Часть C. Чтение логов

  1. Найдите в /var/log/auth.log успешные и неудачные входы через grep.
  2. Напишите однострочник, считающий неудачные входы.
  3. В Windows-ВМ найдите события 4624 и 4625 в Event Viewer.

Дополнительные лабораторные

Часть D. Разбор Windows-логов

  1. В Windows-ВМ открой Event Viewer → Security.
  2. Найди события 4624 (успешный вход) и 4625 (отказ).
  3. Определи, как выглядел бы перебор паролей в этих событиях.

Часть E. Процессы и автозагрузка

  1. Выведи список процессов (ps aux в Linux).
  2. Посмотри, что стартует автоматически.
  3. Объясни, почему вредонос стремится попасть в автозагрузку.
