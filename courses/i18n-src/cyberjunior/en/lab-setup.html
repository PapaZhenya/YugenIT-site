Composition

A single isolated bench for all of the course's practicals: the attacking machine and the targets "see" only each other, not your home/work network, and (for the targets) not the internet.

Requirements

ParameterMinimumRecommended
RAM8 GB16 GB+
Storage60 GB120 GB SSD
CPU2 cores + VT-x/AMD-V4+ cores
If VMs won't start or run slowly, it's almost always because VT-x/AMD-V is disabled in the BIOS/UEFI. On Windows, disable the Hyper-V component if there's a conflict.

Steps

1. Isolated network (do this first!)

⚠️ The targets are intentionally vulnerable — they must never be exposed to the internet.
  1. In VirtualBox, create a Host-Only or Internal Network (e.g. lab-net), subnet 10.10.10.0/24.
  2. Adapter layout:
    • Kali: Internal Network lab-net plus NAT (internet as needed).
    • Targets: Internal Network lab-net only (no NAT!).
  3. Verify isolation: from the target, ping 8.8.8.8 should get NO response; from Kali, ping <target IP> should succeed.

2. Kali Linux

  1. Download the ready-made Kali image for VirtualBox from kali.org.
  2. Import it and configure the adapters as described above.
  3. Log in (kali/kali), change the password.
  4. Update: sudo apt update && sudo apt -y full-upgrade.

3. Metasploitable 2

  1. Download the Metasploitable 2 image.
  2. Create a VM (512–1024 MB), attach the disk.
  3. The only adapter — Internal Network lab-net.
  4. Log in (msfadmin/msfadmin), find its IP: ip addr.

4. Web targets (Docker)

sudo apt update && sudo apt -y install docker.io
sudo systemctl enable --now docker
sudo docker run -d -p 80:80  --name dvwa  vulnerables/web-dvwa
sudo docker run -d -p 3000:3000 --name juice bkimminich/juice-shop

Check from Kali: http://<IP>/ (DVWA) and http://<IP>:3000/ (Juice Shop).

Docker pulls images from the internet once. Download them with NAT temporarily enabled, then switch the adapter back to Internal Network.

5. Snapshots

  • After the clean setup of EACH machine — take a clean snapshot.
  • Before a risky exercise — take one more snapshot.
  • After breaking something — roll back to clean (right-click → Snapshots → Restore).

Readiness checklist

  • VirtualBox + Extension Pack installed
  • Virtualization enabled, VMs start quickly
  • Internal network lab-net created
  • Kali: lab-net + NAT adapters, system updated
  • Metasploitable: lab-net only, IP known
  • Web targets open from Kali
  • NO internet from the target (ping 8.8.8.8 fails)
  • Ping succeeds from Kali to all targets
  • Every VM has a clean snapshot
  • (opt.) SIEM is receiving events

Common issues

SymptomSolution
VM won't start / runs slowlyEnable VT-x/AMD-V; disable Hyper-V on Windows
Kali can't see the targetBoth machines on the same "Internal Network lab-net" adapter
Target reaches the internetRemove NAT/bridged mode, keep only the internal network
Docker won't pull imagesTemporarily enable NAT, download, then switch back to the internal network
Everything freezesRun only the VMs you need; SIEM on demand only
Broke the targetRoll back to the clean snapshot
