Week 4 of the "Attack" block introduces reconnaissance and scanning: it teaches you to distinguish passive from active information gathering and to build a map of a target using Nmap.

Module goals

  • Distinguish passive from active reconnaissance
  • Scan networks and services with Nmap
  • Build a target map as the basis for vulnerability hunting

What it looks like (diagram)

Stages of reconnaissance:

Passive (stealthy) -> whois, DNS, social media, leaks
        |
Active (leaves traces) -> port scanning (Nmap)
        |
Target map: host -> ports -> services -> versions -> risk

Summary

Any attack begins with information gathering. A defender studies the same techniques to see the infrastructure through the adversary's eyes.

Passive and active reconnaissance. Passive (OSINT) gathers data from open sources without contacting the target (whois, DNS, social media, leaked databases) — it's stealthy. Active reconnaissance is direct scanning, which leaves traces in logs.

Nmap — the working tool.

  • -sn — discover live hosts without port scanning.
  • -sV — determine service versions (key for finding vulnerabilities).
  • -p- — all 65535 ports.
  • -A — aggressive: OS, versions, scripts.

An outdated service version is dangerous because known vulnerabilities have already been published for it — an attacker just needs to apply an existing exploit.

Going deeper

Passive reconnaissance (OSINT) in more detail

OSINT is gathering from open sources without contacting the target: domains (whois), DNS records, public documents, employees' social media, leaked databases. This matters for defenders too: it's useful to know what's visible about your organization from the outside, and to reduce unnecessary exposure.

How to read scan results

Nmap shows ports, services, and versions. The key factor for risk assessment is versions: an outdated service often has known vulnerabilities with ready-made exploits. A defender runs Nmap against their own network to find stray and outdated services before an attacker does.

Service fingerprinting and banners

Many services "introduce themselves" on connection — reporting a version (a banner). This is used to identify exactly what's running. For defense, it's useful to strip unnecessary information from banners so as not to make reconnaissance easier.

Another example: why a defender scans themselves

An admin runs Nmap against their own network once a month and finds a forgotten test server with an open port and an old service version. They close it before an attacker finds it. Scanning "yourself" isn't an attack — it's hygiene: you see your own attack surface through the adversary's eyes.

Step-by-step walkthrough: from IP to a target map (in the lab)

  1. Discover live hosts on your lab network: nmap -sn <range>.
  2. Scan the lab machine: nmap -sV <IP>.
  3. Record the open ports and services.
  4. Note the versions and flag the outdated ones.
  5. Build a table: host → port → service → version → risk.

Mini-project: a scan report (in the lab)

On a lab machine (Metasploitable), perform reconnaissance and produce a mini-report:

  • target, method, date;
  • a table of discovered services and versions;
  • for 3 services — why the outdated version is dangerous;
  • recommendations (what to close/update).
⚠️ Only your own lab or explicitly authorized targets. Scanning someone else's network is illegal.

Key terms

  • OSINT — reconnaissance using open sources.
  • Passive / active reconnaissance — without contact / with contact (leaves traces).
  • Nmap — a network and service scanner.
  • Banner — a service's self-announced version.
  • Target map — a summary of host/port/service/version/risk.

Common mistakes and myths

  • Myth: scanning = hacking. On its own it's reconnaissance, but scanning someone else's network is illegal.
  • Mistake: ignoring versions. Old versions are exactly what carry known vulnerabilities.
  • Myth: if a port is open, it's safe because "it was configured that way." Every port is a potential entry point.
  • Mistake: scanning whatever you like. Only your own or explicitly authorized targets.

Frequently asked questions (FAQ)

  • Is Nmap legal? The tool is; legality depends on WHAT you scan.
  • Why does a defender need reconnaissance? To see their own attack surface before the adversary does.
  • Is passive reconnaissance really stealthy? Yes, it doesn't touch the target directly.
  • What should you do with a discovered old service? Update it or shut it down.

Module cheat sheet

  • Reconnaissance: passive (OSINT) → active (scanning).
  • Nmap: -sn (hosts), -sV (versions), -p- (all ports), -A (aggressive).
  • Outdated version = known vulnerabilities.
  • The output is a target map.
  • Only your own lab / authorized targets.

Part A. Passive reconnaissance

  2. Record what you learned without a single active request.

Part B. Discovering hosts and ports

  1. Discover live hosts: nmap -sn <range>.
  2. Scan Metasploitable: nmap -sV <IP>.
  3. Record the open ports and services.

Part C. Target map

  1. Determine the service versions and flag the outdated ones.
  2. Build a table: host → port → service → version → risk.
  3. Write up a scan report (target, method, findings).

Additional lab work

Part D. Passive reconnaissance (safe)

  1. For a training domain, collect open data (whois, public DNS records).
  2. Note what you learned without contacting the target.

Part E. Version comparison

  1. For 3 services from your scan, find the current version.
  2. Rate the risk of being outdated on a low/medium/high scale.
