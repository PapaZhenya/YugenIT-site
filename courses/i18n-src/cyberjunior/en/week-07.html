Summary

Now that the student has seen how systems get broken into, they're ready to harden them. Defense rests on two pillars: hardening (remove what's unnecessary) and cryptography (protect what's left).

Hardening. Reducing the attack surface: disable unnecessary services, close ports, update software, minimal privileges, a firewall. Rooted in the principle of least privilege.

Symmetric vs. asymmetric. Symmetric (AES) uses one shared key — fast, but it raises the problem of key delivery. Asymmetric (RSA) uses a key pair (the public key encrypts, the private key decrypts), which solves the exchange problem but is slower.

Hashing ≠ encryption. Hashing (SHA-256) is irreversible, used for integrity checks and password storage. Encryption is reversible with a key. Confusing the two is a common mistake.

How TLS ties it all together. The parties use asymmetric crypto to verify the certificate and agree on a session key, then encrypt the exchange with a fast symmetric algorithm.

Deeper dive

Symmetric, asymmetric, and hashing — when to use which

Three tools, three jobs. Symmetric (AES) — fast encryption of large data (requires a shared key). Asymmetric (RSA) — securely exchange a key and sign data (a key pair). Hashing (SHA-256) — integrity checks and password storage (irreversible). Confusing them is a classic mistake; each has its own role.

How TLS works (HTTPS under the hood)

TLS combines both approaches: the parties use asymmetric crypto to verify the certificate and agree on a secret session key, then encrypt the exchange with a fast symmetric algorithm. This achieves both a secure key exchange and speed. The padlock icon in your browser is TLS working correctly.

Digital signatures and certificates

Asymmetric crypto provides not just encryption but also signing: you sign with the private key and verify with the public key. This underpins website certificates (proving authenticity) and update integrity checks. Understanding signatures is key to trust on the network.

One more example: why hash ≠ encryption

A developer "encrypted" passwords, but actually used a hash — and now can't "decrypt" them for recovery. That's actually correct! Passwords should be stored irreversibly (hash + salt); they aren't recovered, they're reset. A file that needs to be read back later, on the other hand, should be encrypted (reversible, with a key). One example, and the "hash vs. encryption" distinction sticks for good.

Step-by-step walkthrough: basic Linux server hardening

  1. Update the system and software (close known holes).
  2. Disable unnecessary services and close unused ports.
  3. Configure the firewall (ufw): deny everything, allow only what's needed.
  4. Disable SSH password login, keep only key-based login.
  5. Set up minimal privileges and separate accounts.
  6. Write a checklist and repeat it for every deployment.

Key terms

  • Hardening — reducing the attack surface.
  • AES / RSA — symmetric / asymmetric encryption.
  • SHA-256 — a hash (integrity, passwords).
  • TLS — a secure channel (HTTPS).
  • Digital signature / certificate — proof of authenticity.
  • Least privilege — a core defense principle.

Common mistakes and myths

  • Myth: hashing is encryption. A hash is irreversible; encryption is reversible with a key.
  • Mistake: storing passwords with encryption. Passwords should be hashed (+ salt); they're not meant to be recovered.
  • Myth: hardening breaks convenience. It only removes what's unnecessary; risk goes down, work isn't affected.
  • Mistake: rolling your own "homemade" algorithms. Use proven ones (AES, RSA, SHA-2).

Frequently asked questions (FAQ)

  • Which is faster — AES or RSA? AES (symmetric); RSA is slower, so it's only used to exchange a key.
  • Why does a website need a certificate? To prove authenticity and enable encryption (HTTPS).
  • When hash, when encryption? Hash — integrity/passwords; encryption — when the data needs to be recovered.
  • Where do I start hardening a server? Updates, closing what's unnecessary, and SSH keys.

Module cheat sheet

  • AES — fast, one key. RSA — key pair, exchange/signing. SHA-256 — a hash (irreversible).
  • TLS = asymmetric crypto (key exchange) + symmetric crypto (data).
  • Hardening: update, close what's unnecessary, firewall, SSH keys, minimal privileges.
  • Passwords — hash with salt, don't encrypt.
  • Don't invent your own crypto — use proven algorithms.
