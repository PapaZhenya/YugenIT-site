Deeper Dive

The Cyber Kill Chain as a Defense Tool

The model describes an attack as a sequence of stages: reconnaissance → delivery → exploitation → persistence → command and control (C2) → actions on objectives. Its value lies in the fact that by breaking any link, the defender disrupts the entire attack. It helps clarify exactly where activity was noticed and what would have stopped it sooner.

MITRE ATT&CK — Blue Team's Common Language

ATT&CK is a knowledge base of real-world techniques, grouped by tactics (why) and techniques (how, with an ID like T1566). It's a shared language: analysts describe attacker behavior consistently, know what to look for in logs, and where to place detections. The ability to map an incident to ATT&CK is a key skill.

Threat Hunting: Searching Without Waiting for an Alert

Hunting is a proactive search for threats that rules didn't catch. The analyst forms a hypothesis ("if the attacker gained persistence, there will be traces in autostart") and checks it against the data. This is what separates a mature SOC from a reactive "wait for the alert" approach.

One More Example: A Suspicious Process Chain

In the logs, WINWORD.EXE launches powershell, which reaches out over the network to an unknown IP, and then something accesses lsass. Individually — "noise"; together — a classic chain: phishing document → code execution → C2 → credential theft. Blue Team catches exactly these kinds of combinations, and ATT&CK gives them names. This is how scattered events come together into a coherent attack story.

Step-by-Step Walkthrough: Mapping an Incident to ATT&CK

  1. Take the incident events (dataset scenario2_phish_hunt).
  2. For each step, determine the tactic (why) and the technique (how, ID).
  3. Start with the obvious: phishing → T1566, autostart → T1547.
  4. Flag "unexpected process parents" (WINWORD → powershell) and access to lsass.
  5. Assemble a map: tactic → technique → evidence in the logs.

Key Terms

  • Cyber Kill Chain — stages of an attack (7 steps).
  • MITRE ATT&CK — a database of tactics and techniques.
  • Tactic / technique — why / how (with an ID).
  • C2 — the attacker's command-and-control channel.
  • Threat hunting — proactive threat searching.
  • Persistence — maintaining a foothold in the system.

Common Mistakes and Myths

  • Myth: monitoring = hunting. Monitoring waits for an alert; hunting starts from a hypothesis.
  • Mistake: looking at events in isolation. The power is in the connections (chains).
  • Myth: ATT&CK is for the "elite". It's a practical tool even for a junior analyst.
  • Mistake: ignoring "unexpected process parents". This is a strong indicator of an attack.

Frequently Asked Questions (FAQ)

  • How does the kill chain differ from ATT&CK? The kill chain is broad stages; ATT&CK is detailed techniques.
  • Do I need to learn every ATT&CK technique? No, master the logic and the common techniques.
  • What is C2? The channel through which the attacker controls the infected machine.
  • Is hunting something a junior can do? Basic hypotheses — yes, and it's great training for your thinking.
