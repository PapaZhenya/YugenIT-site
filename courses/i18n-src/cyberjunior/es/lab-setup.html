Composición

Un único banco aislado para todas las prácticas del curso: la máquina atacante y los objetivos «se ven» solo entre sí, pero no la red doméstica/de trabajo ni (para los objetivos) internet.

RolMáquinaFunción
AtacanteKali LinuxNmap, Wireshark, Burp/ZAP, Hydra, John — bloques 2–4
Objetivo (red)Metasploitable 2Servicios de red vulnerables — semanas 4, 6
Objetivo (web)DVWA + OWASP Juice Shop (Docker)Vulnerabilidades web — semana 5
Defensa (opc.)Ubuntu + Wazuh/ELKSIEM y monitoreo — semanas 7–8, 10

Requisitos

ParámetroMínimoRecomendado
RAM8 GB16 GB+
Espacio60 GB120 GB SSD
CPU2 núcleos + VT-x/AMD-V4+ núcleos
Si las VM no arrancan o van lentas — casi siempre es porque VT-x/AMD-V está desactivado en la BIOS/UEFI. En Windows, si hay conflicto, desactiva el componente Hyper-V.

Pasos

1. Red aislada (¡lo primero!)

⚠️ Los objetivos son deliberadamente vulnerables — no se pueden exponer a internet.
  1. En VirtualBox crea una red Host-Only o Internal Network (p. ej. lab-net), subred 10.10.10.0/24.
  2. Esquema de adaptadores:
    • Kali: Red interna lab-net + NAT (internet cuando sea necesario).
    • Objetivos: solo Red interna lab-net (¡sin NAT!).
  3. Verificación de aislamiento: desde el objetivo ping 8.8.8.8 — NO debe haber respuesta; desde Kali ping <IP del objetivo> — debe funcionar.

2. Kali Linux

  1. Descarga la imagen preconfigurada de Kali para VirtualBox desde kali.org.
  2. Impórtala y configura los adaptadores según el esquema anterior.
  3. Inicia sesión (kali/kali), cambia la contraseña.
  4. Actualiza: sudo apt update && sudo apt -y full-upgrade.

3. Metasploitable 2

  1. Descarga la imagen de Metasploitable 2.
  2. Crea la VM (512–1024 MB), conecta el disco.
  3. Único adaptador — Red interna lab-net.
  4. Inicia sesión (msfadmin/msfadmin), averigua la IP: ip addr.

4. Objetivos web (Docker)

sudo apt update && sudo apt -y install docker.io
sudo systemctl enable --now docker
sudo docker run -d -p 80:80  --name dvwa  vulnerables/web-dvwa
sudo docker run -d -p 3000:3000 --name juice bkimminich/juice-shop

Verifica desde Kali: http://<IP>/ (DVWA) y http://<IP>:3000/ (Juice Shop).

Docker descarga imágenes de internet UNA SOLA VEZ. Descárgalas con NAT activado temporalmente y luego devuelve el adaptador a la Red interna.

5. Snapshots

  • Después de la configuración limpia de CADA máquina — snapshot clean.
  • Antes de una actividad de riesgo — otro snapshot más.
  • Tras una avería — vuelve a clean (clic derecho → Instantáneas → Restaurar).

Lista de verificación de preparación

  • VirtualBox + Extension Pack instalados
  • Virtualización activada, las VM arrancan rápido
  • Red interna lab-net creada
  • Kali: adaptadores lab-net + NAT, sistema actualizado
  • Metasploitable: solo lab-net, IP conocida
  • Los objetivos web se abren desde Kali
  • Desde el objetivo NO hay internet (ping 8.8.8.8 no responde)
  • Desde Kali el ping llega a todos los objetivos
  • Cada VM tiene un snapshot clean
  • (opc.) el SIEM recibe eventos

Problemas frecuentes

SíntomaSolución
La VM no arranca / va lentaActivar VT-x/AMD-V; desactivar Hyper-V en Windows
Kali no ve el objetivoAmbas máquinas en el mismo adaptador «Red interna lab-net»
El objetivo sale a internetQuitar NAT/puente, dejar solo la red interna
Docker no descarga imágenesActivar NAT temporalmente, descargar, restaurar la red interna
Todo se congelaEjecutar solo las VM necesarias; SIEM — bajo demanda
Rompiste el objetivoRestaurar al snapshot clean
