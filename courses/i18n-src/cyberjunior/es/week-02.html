Apuntes

Casi todos los ataques pasan por la red, por lo que comprender la pila de red es una base obligatoria. Los datos se transmiten por capas; cada una añade su propia cabecera.

La pila TCP/IP (simplificada)

  • Enlace de datos — transmisión dentro del segmento local (direcciones MAC).
  • Red (IP) — enrutamiento entre redes según direcciones IP.
  • Transporte (TCP/UDP) — entrega hasta el servicio. TCP es confiable y orientado a conexión, UDP es rápido y sin garantías.
  • Aplicación — HTTP, DNS, SMTP.

Puertos y el handshake de TCP. La IP señala el host, el puerto señala el servicio. TCP se abre mediante un three-way handshake: SYN → SYN-ACK → ACK.

DNS y HTTP frente a HTTPS. DNS convierte un nombre en una IP; a su alrededor se construyen el phishing y el envenenamiento de caché. HTTP transmite datos en texto plano (incluidos los inicios de sesión), HTTPS añade cifrado TLS.

Puertos de memoria: HTTP 80, HTTPS 443, SSH 22, FTP 21, SMTP 25, DNS 53, RDP 3389.

Profundizando en el tema

Interceptación de tráfico y por qué HTTPS es importante para la seguridad de la información

En una red compartida (Wi-Fi abierto), un atacante puede «escuchar» el tráfico ajeno. Si el sitio usa HTTP, los inicios de sesión y los datos se ven en texto plano. HTTPS los cifra, y lo interceptado se vuelve inútil. Para un profesional de seguridad, esto es básico: los protocolos sin cifrar son un objetivo prioritario tanto para el ataque como para la defensa.

Banderas TCP y qué es el «escaneo de puertos»

Una conexión TCP se abre con un handshake (SYN → SYN-ACK → ACK). Las herramientas de escaneo (Nmap) juegan con estos pasos para averiguar qué puertos están abiertos sin completar la conexión completa. Comprender el handshake ayuda a leer logs y a reconocer el escaneo — un primer indicio típico de preparación de un ataque.

El modelo OSI a través de los ojos de un defensor

Cada capa tiene su propia clase de amenazas: en la de enlace de datos, la suplantación de MAC/ARP; en la de red, la suplantación de IP; en la de transporte, el escaneo; en la de aplicación, los ataques web. Conociendo la capa, comprendes tanto el vector de ataque como dónde colocar la defensa. El modelo OSI no es solo teoría, sino también un mapa de amenazas.

Otro ejemplo: el peligro del Wi-Fi abierto

Estás en un café, entras a un sitio por HTTP e introduces tu contraseña. Cualquiera en la misma red con un sniffer sencillo la ve en texto plano. Si el sitio estuviera en HTTPS, el interceptor solo vería basura cifrada. Conclusión para la defensa: usa HTTPS y VPN en redes públicas; para el ataque, este escenario muestra por qué los protocolos abiertos son una presa fácil.

Análisis paso a paso: qué se ve al entrar a un sitio

  1. El dispositivo averigua la IP del sitio mediante DNS.
  2. Abre una conexión TCP (handshake) en el puerto 443.
  3. Se negocia el cifrado TLS (para HTTPS).
  4. Se produce el intercambio de datos cifrado.
  5. En Wi-Fi abierto, un tercero ve a qué IP te conectaste, pero no el contenido (en el caso de HTTPS).

Miniproyecto: mapa de puertos y riesgos

Es el primer paso para reducir la superficie de ataque.

Términos clave

  • TCP/UDP — transporte confiable / rápido.
  • Puerto — «puerta» hacia un servicio (22 SSH, 80 HTTP, 443 HTTPS, 53 DNS).
  • DNS — nombre → IP.
  • HTTP vs HTTPS — abierto / cifrado.
  • Handshake de TCP — SYN → SYN-ACK → ACK.
  • Sniffer — herramienta de interceptación de tráfico (por ej. Wireshark).

Errores y mitos frecuentes

  • Mito: en una red privada no hace falta cifrar. Un atacante interno también es una amenaza.
  • Error: ignorar los puertos abiertos. Cada puerto de más es una entrada potencial.
  • Mito: HTTPS = el sitio es totalmente seguro. HTTPS protege el canal, pero no al sitio mismo frente a sus vulnerabilidades.
  • Error: confundir IP y puerto. IP — el dispositivo, puerto — el servicio.

Preguntas frecuentes (FAQ)

  • ¿Wireshark es una herramienta «de hackers»? No, es un analizador estándar para diagnóstico y defensa.
  • ¿Por qué es tan importante HTTPS? Cifra los datos, anulando la utilidad de la interceptación.
  • ¿Qué es el escaneo de puertos? Comprobar qué servicios están disponibles en un dispositivo.
  • ¿La VPN protege en Wi-Fi abierto? Sí, cifra tu tráfico por encima de la red.

Laboratorio

Parte A. Despliegue del laboratorio

  1. Instala VirtualBox y crea una VM de Kali Linux.
  2. Configura dos adaptadores: NAT (internet) y Host-Only/Internal (red aislada).
  3. Verifica la conectividad con ping dentro de la red de laboratorio.

Parte B. Captura de tráfico HTTP

  1. Ejecuta Wireshark en la interfaz de la red de laboratorio.
  2. Abre un recurso HTTP con un formulario de entrada.
  3. Encuentra el three-way handshake (SYN, SYN-ACK, ACK).
  4. Filtra por HTTP y encuentra los datos del formulario en texto plano.

Parte C. Comparación con HTTPS

  1. Repite la captura al abrir un recurso HTTPS.
  2. Verifica que el contenido esté cifrado.
  3. Anota la conclusión: qué se ve en HTTP y qué queda oculto en HTTPS.

Laboratorios adicionales

Parte D. Compara HTTP y HTTPS en Wireshark

  1. Captura tráfico al entrar a una página HTTP con un formulario — encuentra datos en texto plano.
  2. Repite con HTTPS — verifica que el contenido esté cifrado.
  3. Saca una conclusión de por qué esto es crítico para la seguridad.

Parte E. Inventario de puertos

  1. Elabora una lista de puertos y servicios estándar.
  2. Para tres de ellos, describe por qué es peligrosa su disponibilidad desde internet.
