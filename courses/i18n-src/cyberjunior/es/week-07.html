Esta semana del bloque «Defensa» está dedicada al hardening de servidores y a los fundamentos de la criptografía: cómo reducir la superficie de ataque y usar correctamente el cifrado, el hashing y TLS.

Objetivos del módulo

  • Aplicar los principios de reducción de la superficie de ataque
  • Distinguir el cifrado simétrico, el asimétrico y el hashing
  • Configurar la protección básica de un servidor y comprender TLS

Cómo se ve (esquema)

Cifrado simétrico vs asimétrico:

Simétrico (AES):   una clave  🔑  cifra y descifra (rápido)
Asimétrico (RSA):  un par  🔑pública / 🔒privada  (resuelve el intercambio de claves)
TLS: con asimetría se acuerda la clave -> luego, simétricamente (rápido)

Hardening = reducción de la superficie de ataque:

Antes:   [muchos servicios][puertos abiertos][software antiguo][777]
Después:[solo lo necesario][puertos cerrados][actualizado][mínimos permisos]

Apuntes

Después de ver cómo se rompen los sistemas, el estudiante está listo para reforzarlos. La defensa se apoya en dos pilares: el hardening (eliminar lo innecesario) y la criptografía (proteger el resto).

Hardening. Reducción de la superficie de ataque: desactivar servicios innecesarios, cerrar puertos, actualizar el software, permisos mínimos, firewall. En su base está el principio del mínimo privilegio.

Simétrico frente a asimétrico. El simétrico (AES) usa una clave compartida, es rápido, pero surge el problema de transmitir la clave. El asimétrico (RSA) usa un par de claves (la pública cifra, la privada descifra), resuelve el intercambio, pero es más lento.

Hashing ≠ cifrado. El hashing (SHA-256) es irreversible, sirve para la integridad y el almacenamiento de contraseñas. El cifrado es reversible mediante una clave. Confundirlos es un error típico.

Cómo lo une todo TLS. Las partes usan asimetría para verificar el certificado y acordar una clave de sesión, luego cifran el intercambio con un algoritmo simétrico rápido.

Profundizando en el tema

Simetría, asimetría y hashing — cuándo usar cada uno

Tres herramientas, tres tareas. Simétrico (AES) — cifrar grandes volúmenes de datos rápidamente (requiere una clave compartida). Asimétrico (RSA) — intercambiar claves de forma segura y firmar (par de claves). Hashing (SHA-256) — verificación de integridad y almacenamiento de contraseñas (irreversible). Confundirlos es un error clásico; cada uno tiene su propio papel.

Cómo funciona TLS (HTTPS por dentro)

TLS combina ambos enfoques: las partes, mediante asimetría, verifican el certificado y acuerdan una clave de sesión secreta, y luego cifran el intercambio con un algoritmo simétrico rápido. Así se logra tanto la seguridad del intercambio de claves como la velocidad. El candado en el navegador es TLS funcionando.

Firma digital y certificados

La asimetría no solo permite cifrar, sino también firmar: se firma con la clave privada, se verifica con la pública. Sobre esto se sustentan los certificados de los sitios web (que demuestran autenticidad) y la verificación de integridad de las actualizaciones. Comprender la firma es clave para la confianza en la red.

Otro ejemplo: por qué hash ≠ cifrado

Un desarrollador «cifró» las contraseñas, pero en realidad usó un hash — y ahora no puede «descifrarlas» para recuperarlas. ¡Esto es correcto! Las contraseñas deben almacenarse de forma irreversible (hash + sal), no se recuperan, se restablecen. En cambio, un archivo que luego debe leerse se cifra (de forma reversible, con una clave). Con un solo ejemplo, la diferencia «hash vs cifrado» queda asimilada para siempre.

Análisis paso a paso: hardening básico de un servidor Linux

  1. Actualiza el sistema y el software (cierra brechas conocidas).
  2. Desactiva los servicios innecesarios y cierra los puertos sobrantes.
  3. Configura el firewall (ufw): denegar todo, permitir solo lo necesario.
  4. Desactiva el acceso por contraseña en SSH, deja solo el acceso por llaves.
  5. Configura permisos mínimos y cuentas separadas.
  6. Elabora una lista de verificación y repítela en cada despliegue.

Términos clave

  • Hardening — reducción de la superficie de ataque.
  • AES / RSA — cifrado simétrico / asimétrico.
  • SHA-256 — hash (integridad, contraseñas).
  • TLS — canal protegido (HTTPS).
  • Firma digital / certificado — confirmación de autenticidad.
  • Mínimo privilegio — principio básico de protección.

Errores y mitos frecuentes

  • Mito: el hash es un tipo de cifrado. El hash es irreversible; el cifrado es reversible mediante una clave.
  • Error: almacenar contraseñas cifradas. Las contraseñas se hashean (+ sal), no se recuperan.
  • Mito: el hardening rompe la comodidad. Solo elimina lo innecesario; el riesgo baja, el trabajo no se ve afectado.
  • Error: usar algoritmos «caseros» propios. Usa los ya probados (AES, RSA, SHA-2).

Preguntas frecuentes (FAQ)

  • ¿Qué es más rápido, AES o RSA? AES (simétrico); RSA es más lento, por eso solo se usa para intercambiar la clave.
  • ¿Para qué sirve el certificado de un sitio? Para demostrar autenticidad y habilitar el cifrado (HTTPS).
  • ¿Cuándo usar hash y cuándo cifrado? Hash — integridad/contraseñas; cifrado — cuando los datos deben poder recuperarse.
  • ¿Por dónde empezar a proteger un servidor? Por las actualizaciones, cerrar lo innecesario y las llaves SSH.

Chuleta del módulo

  • AES — rápido, una clave. RSA — par de claves, intercambio/firma. SHA-256 — hash (irreversible).
  • TLS = asimetría (intercambio de clave) + simetría (datos).
  • Hardening: actualizar, cerrar lo innecesario, firewall, llaves SSH, permisos mínimos.
  • Las contraseñas — hashearlas con sal, no cifrarlas.
  • No inventes tu propia criptografía — usa lo probado.
