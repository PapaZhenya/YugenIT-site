Конспект

Майже кожна атака проходить через мережу, тому розуміння мережевого стека — обов'язкова база. Дані передаються за рівнями; кожен додає свій заголовок.

Стек TCP/IP (спрощено)

  • Канальний — передача всередині локального сегмента (MAC-адреси).
  • Мережевий (IP) — маршрутизація між мережами за IP-адресами.
  • Транспортний (TCP/UDP) — доставка до служби. TCP надійний і зі встановленням з'єднання, UDP швидкий і без гарантій.
  • Прикладний — HTTP, DNS, SMTP.

Порти і рукостискання TCP. IP вказує на хост, порт — на службу. TCP відкривається через three-way handshake: SYN → SYN-ACK → ACK.

DNS і HTTP проти HTTPS. DNS перетворює ім'я на IP; навколо нього будуються фішинг і отруєння кешу. HTTP передає дані відкритим текстом (включно з логінами), HTTPS додає TLS-шифрування.

Порти напам'ять: HTTP 80, HTTPS 443, SSH 22, FTP 21, SMTP 25, DNS 53, RDP 3389.

Глибше в тему

Перехоплення трафіку і чому HTTPS важливий для ІБ

У спільній мережі (відкритий Wi-Fi) зловмисник може «слухати» чужий трафік. Якщо сайт на HTTP, логіни та дані видно відкритим текстом. HTTPS шифрує їх, і перехоплене стає марним. Для безпекознавця це база: незашифровані протоколи — пріоритетна ціль і для атаки, і для захисту.

TCP-прапорці і що таке «сканування портів»

TCP-з'єднання відкривається рукостисканням (SYN → SYN-ACK → ACK). Інструменти сканування (Nmap) грають із цими кроками, щоб дізнатися, які порти відкриті, не завершуючи повне з'єднання. Розуміння рукостискання допомагає читати логи і розпізнавати сканування — типова перша ознака підготовки атаки.

Модель OSI очима захисника

Кожен рівень — свій клас загроз: на канальному — підміна MAC/ARP, на мережевому — підміна IP, на транспортному — сканування, на прикладному — атаки на веб. Знаючи рівень, ти розумієш і вектор атаки, і де ставити захист. Модель OSI — не лише теорія, а й карта загроз.

Ще один приклад: небезпека відкритого Wi-Fi

Ти в кафе, заходиш на сайт через HTTP і вводиш пароль. Будь-хто в тій самій мережі з простим сніфером бачить його відкритим текстом. Якби сайт був на HTTPS, перехоплювач побачив би лише зашифроване сміття. Висновок для захисту: використовуй HTTPS і VPN у публічних мережах; для атаки цей сценарій показує, чому відкриті протоколи — легка здобич.

Покроковий розбір: що видно під час входу на сайт

  1. Пристрій дізнається IP сайту через DNS.
  2. Відкриває TCP-з'єднання (рукостискання) на порт 443.
  3. Узгоджується TLS-шифрування (для HTTPS).
  4. Йде зашифрований обмін даними.
  5. У відкритому Wi-Fi сторонній бачить: до якого IP ти підключився, але не вміст (для HTTPS).

Міні-проєкт: карта портів і ризиків

Для навчальної машини (або свого ПК) склади таблицю:

  • які порти відкриті (дізнаєшся в модулі 4 через Nmap, поки — відомі);
  • яка служба за кожним;
  • чим небезпечний відкритий порт;
  • чи потрібен він взагалі (зайве — закрити).

Це перший крок до скорочення поверхні атаки.

Ключові терміни

  • TCP/UDP — надійний / швидкий транспорт.
  • Порт — «двері» до служби (22 SSH, 80 HTTP, 443 HTTPS, 53 DNS).
  • DNS — ім'я → IP.
  • HTTP vs HTTPS — відкрито / зашифровано.
  • Рукостискання TCP — SYN → SYN-ACK → ACK.
  • Сніфер — інструмент перехоплення трафіку (напр. Wireshark).

Часті помилки та міфи

  • Міф: у приватній мережі можна не шифрувати. Внутрішній зловмисник теж загроза.
  • Помилка: ігнорувати відкриті порти. Кожен зайвий порт — потенційний вхід.
  • Міф: HTTPS = сайт безпечний повністю. HTTPS захищає канал, але не сам сайт від вразливостей.
  • Помилка: плутати IP і порт. IP — пристрій, порт — служба.

Часті запитання (FAQ)

  • Wireshark — це «хакерський» інструмент? Ні, це стандартний аналізатор для діагностики та захисту.
  • Чому HTTPS такий важливий? Він шифрує дані, знецінюючи перехоплення.
  • Що таке сканування портів? Перевірка, які служби доступні на пристрої.
  • VPN захищає у відкритому Wi-Fi? Так, він шифрує твій трафік поверх мережі.

Шпаргалка модуля

  • Порти: 22/80/443/53/21/25/3389 — знати напам'ять.
  • HTTP відкритий, HTTPS зашифрований. У публічних мережах — HTTPS/VPN.
  • Рукостискання: SYN → SYN-ACK → ACK.
  • Кожен рівень OSI = свій клас загроз.
  • Відкритий порт = потенційна точка входу.

Лабораторна робота

Частина A. Розгортання лабораторії

  1. Встановіть VirtualBox і створіть ВМ Kali Linux.
  2. Налаштуйте два адаптери: NAT (інтернет) і Host-Only/Internal (ізольована мережа).
  3. Перевірте зв'язність ping всередині лаб-мережі.

Частина B. Захоплення трафіку HTTP

  1. Запустіть Wireshark на інтерфейсі лаб-мережі.
  2. Відкрийте HTTP-ресурс із формою введення.
  3. Знайдіть three-way handshake (SYN, SYN-ACK, ACK).
  4. Відфільтруйте HTTP і знайдіть дані форми у відкритому вигляді.

Частина C. Порівняння з HTTPS

  1. Повторіть захоплення під час відкриття HTTPS-ресурсу.
  2. Переконайтеся, що вміст зашифрований.
  3. Зафіксуйте висновок: що видно в HTTP і приховано в HTTPS.

Додаткові лабораторні

Частина D. Порівняй HTTP і HTTPS у Wireshark

  1. Захопи трафік під час входу на HTTP-сторінку з формою — знайди дані відкритим текстом.
  2. Повтори з HTTPS — переконайся, що вміст зашифрований.
  3. Зроби висновок, чому це критично для безпеки.

Частина E. Інвентаризація портів

  1. Склади список стандартних портів і служб.
  2. Для трьох із них опиши, чим небезпечна їхня доступність з інтернету.

Завдання для самостійної роботи

  • Намалюйте схему шляху пакета з підписом кожного рівня та заголовка.
  • Поясніть, чому вхід через HTTP у публічному Wi-Fi небезпечний і що змінює HTTPS.

Додаткові завдання

  • Поясни, чому відкритий Wi-Fi без HTTPS небезпечний.
  • Намалюй шлях пакета і відзнач, де його може перехопити зловмисник.
  • Зістав 3 рівні OSI з типовими для них атаками.
  • Поясни різницю між TCP і UDP з погляду безпекознавця.
