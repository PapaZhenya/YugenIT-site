Третій тиждень блоку «Фундамент» вчить впевнено працювати в командному рядку Linux, розбиратися в моделі прав доступу і знаходити сліди подій у системних журналах Linux і Windows.

Цілі модуля

  • Впевнено навігувати в Linux із командного рядка
  • Розуміти модель прав і принцип найменших привілеїв
  • Знаходити і читати системні журнали Linux і Windows

Як це виглядає (схема)

Права доступу в Linux (rwx):

-rwxr-x---   владелец: rwx   группа: r-x   остальные: ---
 ^ файл       (чтение/запись/выполнение)
777 = rwx для ВСЕХ = опасно

Де шукати сліди (журнали):

Linux:   /var/log/auth.log  (входы, sudo)
         /var/log/syslog    (система)
Windows: Event Viewer -> Security (4624 вход, 4625 отказ)

Конспект

Інструменти ІБ живуть у командному рядку, а розслідування починається з журналів.

Файлова система і права Linux. Дерево від кореня /, все є файлом. Права — три набори (власник/група/інші) у вигляді rwx. chmod змінює права, chown — власника, sudo дає тимчасові привілеї root. Надлишкові права (777) — часта причина компрометації.

Журнали як джерело істини. У Linux — /var/log (auth.log — входи, syslog — система). У Windows — Event Viewer: Security (входи 4624 успішний, 4625 невдалий), System, Application.

Active Directory на пальцях. У корпоративному середовищі Windows-машини в домені під керуванням Active Directory — каталогу користувачів, груп і політик. Розуміння AD критичне для Blue Team, бо саме його атакують для захоплення всієї мережі.

Глибше в тему

Користувачі, групи і root

У Linux у кожного процесу є власник. root — суперкористувач, може все. Звичайні користувачі обмежені; sudo дає тимчасове підвищення до root. Атакуючі прагнуть саме до root («підвищення привілеїв»), а захист — тримати користувачів на мінімумі прав. Розуміння цієї моделі — основа і атаки, і захисту.

Підвищення привілеїв (у двох словах)

Часто атакуючий спершу отримує доступ звичайного користувача, а потім шукає спосіб стати root: неправильні права на файли, вразливі програми з прапорцем підвищення, слабкі налаштування sudo. Завдання захисника — не залишати таких лазівок. У цьому курсі ми дивимося на це концептуально і лише в лабораторії.

Процеси, служби та автозавантаження

Система — це безліч працюючих процесів і служб. Шкідливе ПЗ часто маскується під системний процес і прописується в автозавантаження, щоб пережити перезавантаження. Тому вміння дивитися список процесів і автозапуск — базова навичка розслідування (стане в пригоді на тижнях 9–10).

Ще один приклад: небезпека прав 777

Розробник надав конфігураційному файлу права 777 «щоб працювало». Тепер будь-який користувач системи може його прочитати і змінити — включно із секретами в ньому. Атакуючий, що отримав навіть низькі права, підмінює файл і підвищує привілеї. Висновок: права — не формальність, а поверхня атаки. Правильно — мінімально необхідні права.

Покроковий розбір: знаходимо невдалі входи в журналі

  1. Відкрий /var/log/auth.log.
  2. Відфільтруй рядки зі словами Failed password: grep "Failed password" auth.log.
  3. Порахуй їх: додай | wc -l.
  4. Знайди, з яких IP йшли спроби: grep "Failed password" auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn.
  5. Багато спроб з одного IP → ймовірний перебір паролів.

Міні-проєкт: шпаргалка команд + аудит прав

Збери свій робочий інструмент:

  • шпаргалка з 20 команд Linux з описом;
  • на навчальній ВМ знайди файли з надлишковими правами (наприклад, доступні на запис усім);
  • запропонуй, як їх виправити;
  • оформи короткий звіт «аудит прав».

Ключові терміни

  • root — суперкористувач Linux.
  • sudo — тимчасове підвищення прав.
  • rwx / chmod — права доступу та їхня зміна.
  • auth.log / syslog — журнали Linux.
  • Event ID 4624/4625 — вхід/відмова у Windows.
  • Підвищення привілеїв — отримання вищих прав.
  • Автозавантаження — механізм запуску при старті (часте місце персистенції).

Часті помилки та міфи

  • Міф: журнали ніхто не читає, отже вони не потрібні. Журнали — головне джерело істини під час розслідування.
  • Помилка: ставити 777 «щоб працювало». Це відчинені двері.
  • Міф: root потрібен для всього. Навпаки — працюй із мінімумом прав.
  • Помилка: довіряти history -c. Сліди часто залишаються в інших журналах.

Часті запитання (FAQ)

  • Чи обов'язково знати Linux? Так, це основний інструмент безпекознавця.
  • Навіщо читати журнали вручну, якщо є SIEM? Розуміння журналів — база; SIEM лише автоматизує.
  • Що важливіше — Linux чи Windows? Обидва: сервери часто на Linux, корпоративне середовище — Windows/AD.
  • Що таке підвищення привілеїв? Отримання вищих прав, ніж видано спочатку.

Шпаргалка модуля

  • Навігація: pwd ls -la cd cat less grep head tail.
  • Права: chmod, модель rwx (власник/група/інші), 777 — небезпечно.
  • Підвищення: sudo; ціль атакуючого — root.
  • Журнали: /var/log/auth.log, syslog; Windows — Event Viewer (4624/4625).
  • Порахувати невдалі входи: grep "Failed password" auth.log | wc -l.

Лабораторна робота

Частина A. Навігація і файли

  1. Освойте: pwd, ls -la, cd, cat, less, head, tail, grep.
  2. Створіть каталог і файли, потренуйтесь переміщатися і переглядати.

Частина B. Права доступу

  1. Створіть користувача і файл; змінюйте права через chmod.
  2. Перевірте, що може і не може інший користувач.
  3. Покажіть, чому права 777 на файл із секретом небезпечні.

Частина C. Читання журналів

  1. Знайдіть у /var/log/auth.log успішні та невдалі входи через grep.
  2. Напишіть однорядковий скрипт, що рахує невдалі входи.
  3. У Windows-ВМ знайдіть події 4624 і 4625 в Event Viewer.

Додаткові лабораторні

Частина D. Розбір Windows-журналів

  1. У Windows-ВМ відкрий Event Viewer → Security.
  2. Знайди події 4624 (успішний вхід) і 4625 (відмова).
  3. Визнач, як виглядав би перебір паролів у цих подіях.

Частина E. Процеси і автозавантаження

  1. Виведи список процесів (ps aux у Linux).
  2. Подивись, що стартує автоматично.
  3. Поясни, чому шкідливе ПЗ прагне потрапити в автозавантаження.
