Модуль блоку «Реагування» показує, як використовувати Cyber Kill Chain і MITRE ATT&CK для розбору кібератак і вести проактивний threat hunting у роботі Blue Team.

Цілі модуля

  • Використовувати Cyber Kill Chain для аналізу атаки
  • Зіставляти дії з MITRE ATT&CK
  • Практикувати threat hunting за гіпотезою

Як це виглядає (схема)

Cyber Kill Chain — перерви будь-яку ланку:

Розвідка -> Доставка -> Експлуатація -> Закріплення -> C2 -> Дії біля цілі
   |           |            |              |           |         |
   перерви БУДЬ-ЯКИЙ етап -> вся атака зірвана

MITRE ATT&CK — тактики та техніки:

Тактика (навіщо): Initial Access | Persistence | Exfiltration ...
Техніка (як):      T1566 фішинг   | T1547 автозапуск | T1041 вивантаження

Конспект

Реактивне розслідування — половина роботи Blue Team. Друга — проактивний пошук і системне розуміння тактики атакуючих.

Cyber Kill Chain. Етапи: розвідка → доставка → експлуатація → закріплення → керування (C2) → дії біля цілі. Перервавши будь-яку ланку, захисник зриває атаку.

MITRE ATT&CK. База знань про реальні техніки, згруповані за тактиками (навіщо) і техніками (як, з ID на кшталт T1110). Спільна мова Blue Team: що шукати в логах і де ставити детекти.

Threat hunting. Проактивний пошук загроз, які не впіймали правила. Аналітик висуває гіпотезу («якщо атакуючий закріпився — будуть сліди в автозавантаженні») і перевіряє за даними.

Матеріал: датасет «Інцидент №2» (phishing/hunt) — CSV подій SIEM. Студент сам проставляє теги ATT&CK, потім звіряється з тегованою версією. Див. datasets/scenario2_phish_hunt/.

Глибше в тему

Cyber Kill Chain як інструмент захисту

Модель описує атаку за етапами: розвідка → доставка → експлуатація → закріплення → керування (C2) → дії біля цілі. Цінність — у тому, що, перервавши будь-яку ланку, захисник зриває всю атаку. Вона допомагає зрозуміти, де саме була помічена активність і що зупинило б її раніше.

MITRE ATT&CK — спільна мова Blue Team

ATT&CK — база реальних технік, згрупованих за тактиками (навіщо) і техніками (як, з ID на кшталт T1566). Це спільна мова: аналітики описують поведінку атакуючого однаково, знають, що шукати в логах і де ставити детекти. Уміння картувати інцидент за ATT&CK — ключова навичка.

Threat hunting: шукати, не чекаючи алерту

Хантинг — проактивний пошук загроз, які не впіймали правила. Аналітик висуває гіпотезу («якщо атакуючий закріпився, будуть сліди в автозавантаженні») і перевіряє за даними. Це відрізняє зрілий SOC від реактивного «чекаємо алерт».

Ще один приклад: підозрілий ланцюг процесів

У логах WINWORD.EXE запускає powershell, той лізе в мережу на невідомий IP, потім хтось звертається до lsass. Окремо — «шум», разом — класичний ланцюг: фішинговий документ → запуск коду → C2 → крадіжка облікових даних. Blue Team ловить саме такі зв'язки, а ATT&CK дає їм імена. Так розрізнені події складаються в зрозумілу історію атаки.

Покроковий розбір: картуємо інцидент за ATT&CK

  1. Візьми події інциденту (датасет scenario2_phish_hunt).
  2. Для кожного кроку визнач тактику (навіщо) і техніку (як, ID).
  3. Почни з очевидного: фішинг → T1566, автозапуск → T1547.
  4. Познач «несподіваних батьків» процесів (WINWORD → powershell) і доступ до lsass.
  5. Збери карту: тактика → техніка → доказ у логах.

Міні-проєкт: карта ATT&CK інциденту

За датасетом «Інцидент №2» збери:

  • таблицю «крок атаки → тактика → техніка (ID) → доказ»;
  • 3 гіпотези для проактивного хантингу, які впіймали б атаку раніше;
  • по одному правилу детекту на 3 ключові кроки.

Звірся з тегованою версією датасету (у викладача).

Ключові терміни

  • Cyber Kill Chain — етапи атаки (7 кроків).
  • MITRE ATT&CK — база тактик і технік.
  • Тактика / техніка — навіщо / як (з ID).
  • C2 — канал керування атакуючого.
  • Threat hunting — проактивний пошук загроз.
  • Персистенція — закріплення в системі.

Часті помилки та міфи

  • Міф: моніторинг = хантинг. Моніторинг чекає алерт; хантинг іде від гіпотези.
  • Помилка: дивитися події окремо. Сила — у зв'язках (ланцюгах).
  • Міф: ATT&CK — для «еліти». Це робочий інструмент навіть для junior-аналітика.
  • Помилка: ігнорувати «несподіваних батьків» процесів. Це яскрава ознака атаки.

Часті запитання (FAQ)

  • Чим kill chain відрізняється від ATT&CK? Kill chain — великі етапи; ATT&CK — детальні техніки.
  • Чи потрібно вчити всі техніки ATT&CK? Ні, освой логіку та часті техніки.
  • Що таке C2? Канал, через який атакуючий керує зараженою машиною.
  • Хантинг — це для junior? Базові гіпотези — так, чудове тренування мислення.

Шпаргалка модуля

  • Kill Chain: розвідка→доставка→експлуатація→закріплення→C2→дії. Перерви будь-яку ланку.
  • ATT&CK: тактика (навіщо) + техніка (як, Txxxx).
  • Хантинг = гіпотеза → перевірка за даними.
  • Червоні прапорці: WINWORD→powershell, доступ до lsass, автозапуск у реєстрі.
  • Підсумок — карта ATT&CK + правила детекту.
