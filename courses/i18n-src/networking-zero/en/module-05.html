This module explains how a router connects different networks, what a default gateway is, what a routing table and hops are, and what NAT does — plus how to trace a packet's path to an external host.

Module goals

  • Understand the role of a router and how it differs from a switch
  • Understand how a packet moves between networks
  • Understand what a default gateway is
  • Get familiar with the routing table and the concept of a "hop"
  • Understand at a basic level what NAT does
  • Learn to trace a packet's path to an external host

Introduction

A switch works great inside a single network. But how do you get beyond it — into a neighboring network or onto the internet? How does your packet find a server on another continent? That's the router's job — a device that connects different networks and charts a path between them. This is the core of the whole course: once you understand routing, you'll understand how the internet actually works.

Summary

The router: border guard and navigator

The router sits at the junction of different networks and decides where to send a packet next so it gets closer to its destination. The key difference from a switch: a switch moves frames within a single network by MAC addresses, while a router moves packets between networks by IP addresses.

A home router is actually several devices in one box: a router, a switch (the LAN ports), and often a Wi-Fi access point. But its main function is routing — linking your home network to your provider's network, and through it, to the entire internet.

The default gateway: the door outward

When a device wants to send data to a destination outside its own network, it doesn't know the way itself — so it hands the packet to the default gateway. The gateway is the router's address, the "door outward" from the local network. This is the same gateway you've seen in your network settings (usually .1 in your subnet).

The rule is simple: if the destination is in my network, send it directly; if not, hand it to the gateway and let it figure out the rest. Without a configured gateway, a device is "locked" inside its own LAN and can't reach the internet — this, by the way, is a very common cause of "the internet isn't working."

The routing table: the packet's navigator

A router has a routing table — a list of entries like "to reach this network, go through this next step." When it receives a packet, the router looks at the destination address, finds the best-matching entry in the table, and forwards the packet on — to the next router (next hop).

That's how a packet travels: from one router to another, each one bringing it a little closer to its destination, until it reaches the destination network. No single router knows the whole path — it only knows the "next step." It's like a relay race: each runner hands the baton to the next one.

Hops and the packet's path

Each time a packet crosses a router, that's called a hop. Between you and a website there are usually several hops — often 10 to 20. The traceroute command (tracert on Windows) shows this path: it lists the routers the packet passed through and the time to reach each one.

This is an extremely useful diagnostic tool: if a packet "gets stuck" at some hop, you can see exactly where the connection breaks — on your end, at the provider, or further along. We'll come back to this in the module on diagnostics.

NAT: how the whole house goes out under one address

Inside your network there's a bunch of devices with private addresses, but the public address from your provider is usually just one. How do they all reach the internet? Through NAT (Network Address Translation): the router, on the way out, swaps a device's private address for its own public one and remembers who to return the response to. From the outside, your entire house looks like a single address.

This solves the address shortage and also hides the internal structure of the network a bit (from outside, no one can see how many devices you have). More on NAT in the next module, together with DHCP.

Static and dynamic routing (briefly)

Where do the entries in a router's table come from? Two ways. Statically — an administrator enters routes by hand (fine for small networks). Dynamically — routers exchange information about networks among themselves using special protocols and build tables automatically (needed for large networks and the internet). For now it's enough to know both approaches exist; the details of routing protocols are a topic for more advanced courses.

Going deeper

How a router picks a route

A routing table can have several matching entries. The router picks the most specific one (with the longest matching prefix) — the "longest prefix match" principle. If no entry matches, it uses the default route (0.0.0.0/0) — "send everything else there." On a home router, the default route leads to the provider.

What a "default route" is

It's the entry for "all the addresses I don't know." For your PC, the default gateway plays that role; for a home router, it's the link to the provider. Thanks to it, a device doesn't need to know the whole internet — it's enough to know "where to send anything unfamiliar."

Symmetric and asymmetric paths

Usually the response travels roughly the same path as the request, but not necessarily the exact same one — in large networks the "there" and "back" paths can differ. You won't notice this yourself, but it explains why traceroute only shows the path in one direction.

Worked example: a packet's path from you to a website

You open a website hosted on a server in another country. Your laptop sees: the destination isn't in my network, so I'll hand the packet to the gateway (your home router, 192.168.1.1).

The router applies NAT (swaps your private address for its own public one) and, using its table, sends the packet on — to the provider's router. That one looks at the destination address and passes it to the next one, which passes it to the next, and so on. The packet hops from node to node (those very hops), crossing countries, until it reaches the network where the server lives. The response comes back the same way, and your router uses its NAT entry to know the returned packet needs to go to your laptop specifically, not the phone next to it.

Run tracert to any website and you'll literally see this list of hops with your own eyes.

Another example: why without a gateway "local works but there's no internet"

A classic situation: devices in the apartment can ping each other, files move over the local network, but websites won't load. The cause is often one thing — the default gateway is missing or wrong. Local exchange works directly (no gateway needed), but going outward is impossible without the "door." Check the gateway first — and the mystery is solved.

Step-by-step walkthrough: a packet from network A to network B

  1. PC-A1 (network A) wants to reach PC-B1 (network B).
  2. A1 sees: the destination isn't in my network → send to the gateway (the router's interface on network A).
  3. The router checks its table: network B is connected to my second interface.
  4. The router repackages the frame and sends the packet into network B.
  5. PC-B1 receives the packet; the response goes back following the same principle.

Key terms

  • Router — a device that connects different networks and forwards packets by IP
  • Default gateway — the router's address, the "exit" from the local network to the outside
  • Routing table — a list of routes: which network is reached through which next step
  • Hop — a single crossing of a packet through a router
  • NAT — replacing private addresses with a single public one when going out to the internet
  • traceroute / tracert — a command that shows a packet's path via its hops
  • Next hop — the next node the router forwards the packet to

Common mistakes and myths

  • Mistake: confusing a switch with a router. The former works by MAC within a LAN, the latter by IP between networks.
  • Myth: a router knows the whole path to the destination. It only knows the next step.
  • Mistake: forgetting about the gateway. Without a default gateway, a device can't leave its own network.
  • Myth: NAT is protection/a firewall. NAT solves the address shortage; protection is a separate task.
  • Mistake: assuming more hops is always worse. Latency and packet loss matter more than the number of hops.

Frequently asked questions (FAQ)

  • Does a router know the whole path? No, only the next step.
  • What if there's no route for an address? It follows the default route (to the provider).
  • Why does traceroute show the path in only one direction? The response may take a different path.
  • Does NAT protect you? It hides the network a little, but it's not a firewall.
  • Is a home router a router or a switch? Both (plus Wi-Fi) in one box.

Module cheat sheet

  • Router = between networks, by IP. Switch = within a network, by MAC.
  • Default gateway = the door outward from your network.
  • Routing table = "which network is reached through which next step."
  • Longest prefix match — the most specific route is chosen.
  • Default route 0.0.0.0/0 = "send everything unfamiliar here."
  • NAT = many private addresses behind one public one.

Lab work

Part A. Trace the path outward

  1. Run tracert google.com (Windows) or traceroute google.com (Linux/Mac).
  2. Count the number of hops to the destination.
  3. Find the first hop — that's your home router (compare it to the gateway address from module 2).

Part B. Connect two networks in a simulator

  1. In Packet Tracer, create two subnets (two LANs with switches and computers).
  2. Add a router and connect both subnets to it; configure IPs on its interfaces.
  3. Set the correct default gateway on the computers.
  4. Achieve a successful ping between devices on different subnets.

Part C. Break and fix the gateway

  1. On one computer, remove or set an incorrect default gateway.
  2. Try to ping a device on another subnet — confirm it doesn't work.
  3. Restore the correct gateway and confirm connectivity is back.
  4. Draw a conclusion about what the gateway is responsible for.

Part D. Look at the routing table

  1. On the router, display its routing table.
  2. Find the entries for the connected subnets.
  3. Explain how the router uses this table to decide where to send a packet.

Extra labs

Part E. Default route

  1. On the router in the simulator, set a default route to the "provider."
  2. Verify that packets to unknown networks go exactly there.

Part F. Analyze your own traceroute

  1. Run tracert to two different websites.
  2. Compare where the paths coincide (your router, the provider) and where they diverge.
